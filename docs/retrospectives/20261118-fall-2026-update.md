## What went well

- **Measuring first changed the plan.** The charter blamed the 6.1 MB download. The baseline (#33) showed that Pages gzips it to 322 KB, and that the time went into drawing. So the one-file export (#37) was dropped, and the work went into redraws and drawing cost, which gave the 7× load and 12× hover gains.
- **Small steps with one PR each.** Each PR was easy to review and could be reverted on its own. Two phone bugs (#45, #47) were filed, fixed and checked within the epic, rather than becoming follow-up notes.
- **The owner's QA caught what the scripts couldn't.** It found the matching-year picker's missing "click to pin" hint, the averages' rounding, and the phone layout. It also checked on a real phone, after a DevTools simulation showed a misplaced dropdown that turned out to be a DevTools artifact.
- **The runbook was written right after doing the refresh** (#26), so it records real commands, outputs and NOAA's 1–1½ month lag.

## What didn't go well

Mistakes, and what caught them:

- **The perf script counted every redraw twice.** Chart.js 3 assigns `window.Chart` twice, so the wrapper was installed twice. The baseline said 26 redraws on load and 3.6 per hover move, instead of 13 and 1.8. That inflated my hover estimate for #35 (3×, when 1.3–1.6× was right). It was fixed with a guard, and the numbers were corrected in #20, #33, #35 and #36. **Lesson:** sanity-check a new instrument against something with a known answer before trusting it.
- **A false bug report (#28).** The data epic said CLI errors were silent without `--debug`. In fact, tracebacks go to stderr, which hadn't been seen. #28 was closed as not reproducible, and the runbook's advice was corrected (PR #60). **Lesson:** reproduce a bug before filing it as one.
- **Claims made too fast:**
  - I said non-leap years were shifted by a day on the chart. They aren't, because the Feb 29 placeholder keeps them aligned, and I retracted it.
  - A test of "click an empty spot closes the panel" actually clicked a point. It was rerun on a truly empty spot.
  - I added #17 to the Project after the owner had already closed it. I'd worked from a list of open issues taken earlier, and the owner caught it.
- **The phone viewport was missing all along.** It was only noticed during the picker work (#44). It became #45, but it would have been cheaper to find it in the charter's review of the page.
- **The hover target was missed by about 2 ms** (52 vs 50 ms). The owner accepted it: most of what's left is the browser painting the canvas, which only a smaller chart or Chart.js 4 might reduce.
- **Comments were unsigned at first.** Comments are posted from the owner's account, so they now end with a "Written by Claude" footer, as in the Sweepers projects.

## Process notes for Winter 2027

- **The Project's "Item closed" automation is off.** The charter assumed built-in automations would move items to Done, but every status was set by hand. Either turn on the "Item closed" and "Pull request merged" workflows in the Project's settings, or keep setting them by hand.
- **`gh`, `git push` and headless Chrome need to run outside the Claude Code sandbox.** Inside it, `git status` can also list placeholder files (`.bashrc`, `.gitconfig`, …) that aren't really there.
- **The scratchpad can be cleared overnight.** Write issue and PR bodies just before posting, and check that the file exists first.
- **Start the local server before handing off browser QA**, and stop it after merge.
- **Releases:** each quarterly update gets a dated release (`v2027.2.0` next), and a fix between updates bumps the patch, as `v2026.11.1` did.
- **Sharing:** the owner writes and posts. The sharing steps only check that the post is up and linked, after the changelog and release.
- **A charter for Winter 2027?** Probably not for the refresh alone. Epic [#58](https://github.com/klenwell/dr-george/issues/58) and the runbook should be enough. The 1991–2020 normal ([#59](https://github.com/klenwell/dr-george/issues/59)) is its own epic and can go into whichever quarter suits. Write a charter only if a quarter takes on more than one epic of new work.
